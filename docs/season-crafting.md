# 시즌 레시피 재료 보존과 자동 제작

0.4.0부터 현재 시즌 레시피를 읽고 재료를 자동 보존하며 게임의 정상 `NetworkManager.FishCraft`로 제작한다. 사용자 선택에 따라 현재 설치와 새 설치 템플릿에는 `auto_season_craft=true`, `season_goal=collection`, `season_target_grade=5`, `season_target_count=1`을 적용했다. 각 시즌 어종의 1~5성을 각각 1마리씩 보존하며, 상위 제작용 중간 물고기는 추가로 확보한다. 시즌 2의 최종 수집 목표는 총 15마리다. 게임 실행 중 자동화가 켜져 있어야 진행하며 Pause/Observe는 새 제작도 중단한다.

## 확인한 시즌과 레시피

0.4.28부터 재료 확보와 제작 모두 **도깨비불 해파리 → 누더기 프랑켄피시 → 호박 도깨비아귀** 순서로 집중한다. 사용자 가치 우선순위를 `season_species_priority=["FS00040","FS00039","FS00038"]`로 표현하며, 이 순서는 실측 가격을 대신하는 사용자 제작 정책이다. 현재 대상의 1~5성 수집이 끝나기 전에는 다음 어종의 일반 재료를 미리 예약하거나 제작하지 않는다. 해파리 재료가 부족해도 아귀용 저등급 재료를 쌓아 두지 않고 일반 교배·합성에 사용할 수 있게 남긴다. 사용자 잠금·수동 예약·시세 보호와 이미 수집한 모든 시즌 완성품은 계속 보존한다. 현재 대상의 실제 제작이 가능하면 복구 후 교배 재시도보다도 먼저 처리한다.

2026-11-06 실행 중인 게임의 `CommonData.seasonId=2`, 시즌 시작/종료 시각, `GameUtil.IsSeasonActive()`와 `CSVLoader.fishSeasonRecipeList`를 직접 읽었다. 현재 로드된 15개 레시피는 로컬 클라이언트의 시즌 2 테이블과 일치했다. 과거 테이블 파일이 있다는 이유로 그 시즌을 활성으로 취급하지 않는다.

게임의 시즌 2 종료 시각은 **2026-11-27 08:59:59 KST**다. [개발사 공식 시즌 2 공지](https://steamcommunity.com/app/4842670/allnews/)의 11월 26일 23:59 UTC 안내와 일치한다. 공지는 시즌 물고기가 지정 재료의 시즌 합성으로만 생성되고, 시즌 진행 중에는 보관함 반출·장터 거래가 제한된다고 설명한다. 구현은 이 날짜를 하드코딩하지 않고 매번 게임의 현재 시즌 정보를 사용한다.

## 재료를 남기는 방식

1. 목표 어종·등급의 보유 수를 먼저 확인한다. 잠근 완성품도 목표 달성 수에 포함한다.
2. 우선순위가 가장 높은 미완료 어종 하나를 선택하고, 그 어종의 부족한 목표에서 레시피를 거슬러 내려간다. 이미 쓸 수 있는 중간 등급 시즌 물고기가 있으면 그 이전 제작 재료를 다시 모으지 않는다.
3. 현재 집중 어종의 남은 경로에 필요한 일반 어종·별 등급 수량만 예약한다. 후순위 어종의 일반 재료는 미리 묶어 두지 않는다. 남은 교배 횟수가 적은 개체를 우선하고, 같은 조건이면 미배치 개체를 먼저 고른다. 같은 어종의 초과 개체는 기존 일반 자동화에 남긴다.
4. 0.4.3부터 자동 예약 개체는 **일반 합성에서만 제외**하고, 일반 재료의 교배는 별도 조건을 충족하면 허용한다. 부모의 남은 교배 횟수가 줄어도 물고기는 남으므로 레시피 수량은 유지된다. 남은 교배 횟수가 0이 된 개체도 자동 예약을 유지하며 시즌 제작에 사용할 수 있다. 설정의 수동 예약 목록이나 게임 잠금 상태를 바꾸지 않는 동적 예약이다.
5. 정확한 레시피 한 묶음이 사용 가능해지면 시즌 제작을 우선한다. 성공 후 실제 인벤토리를 다시 읽어 다음 등급과 예약량을 재계산한다.
6. 목표를 달성하거나 시즌이 끝나면 불필요해진 일반 재료의 자동 예약을 해제한다. 기존 사용자 잠금·수동 예약은 유지한다.

필요 재료의 어종을 확정적으로 생성하는 교배 조합은 가정하지 않는다. 일반 자동화로 새 물고기가 생길 때마다 레시피 수량에 반영한다. 이 기능은 시즌 수집 목표를 진행하는 정책이며, 시즌 제작의 판매 수익을 최적화하는 경제 모델은 아니다. Economic 모드에서도 완성된 시즌 제작을 먼저 처리한다.

## 보호 조건과 실패 처리

- 사용자 잠금·`reserved_ids`·`reserved_species`·기본종은 시즌 제작에 사용하지 않는다. 잠금을 자동으로 풀지 않는다.
- 일반 재료는 선택한 시세 또는 Grade 보호도 통과해야 한다. 현재 `highest_buy_order`에서는 최고 매수 주문의 수수료 후 수령액이 1,000원 이하이면 허용하며, 확인된 주문 0건은 0원, 미확인 자료는 대기로 처리한다. 다음은 이전 판매 호가 정책의 설명이다. 0.4.17의 `market_merge_price_basis=best_observed_breeds`에서는 같은 어종·현재 별 등급의 실제 관측 매물 중 남은 교배 횟수가 가장 큰 상태를 고르고, 그 상태 매물들의 최고 판매자 호가가 1,000원 이하이면 제작 재료로 허용한다. 이론상 만교배 매물은 요구하지 않는다. 유효 매물 부재·가격 누락·만료는 판단 대기 사유다. `exact_breeds`에서는 이전 현재 개체의 횟수별 기준을 쓴다. Grade 모드에서는 보호 등급 이상의 일반 재료를 소비하지 않으므로 상위 시즌 제작이 대기할 수 있다.
- 자동 시즌 예약과 수동 예약을 합치지 않는다. Protected 계획기, Economic 계획기와 게임의 실행 직전 검사가 모두 교배용 보호와 일반 합성용 보호를 구분한다. 시즌 예약 개체여도 잠금·수동 예약·시세 보호·성숙·쿨타임·잔여 횟수·하트·보유 한도 조건을 통과해야 교배한다. 실제 시즌 물고기의 교배 금지는 유지한다.
- 현재 시즌의 이전 등급 시즌 물고기는 정확히 일치하는 상위 레시피에만 사용할 수 있다. 활성 시즌 물고기는 장터 거래가 제한되므로 그 중간 재료에 일반 장터 조회 완료를 요구하지 않는다. 잠금·수동 예약은 이 예외보다 우선한다.
- 게임 쪽에서 현재 레시피로 할당을 다시 계산해 명령의 시즌·결과 어종/등급·재료 ID 전체가 일치하는지 검증한다. 시즌과 레시피도 추천 버전 해시에 포함하며, 발송 직전 시즌이 계속 활성인지 다시 확인한다.
- 다른 통신·확인 대화상자·미확인 결과가 있으면 보내지 않는다. 0.4.32부터 메뉴·목록·교배 성공 화면을 열어둔 상태는 대기 사유가 아니다. 기존 세션/설정 해시/유효기간 검증과 `pending.json` 기록을 함께 사용한다.
- 게임의 성공 콜백 이후 지정 재료가 전부 사라지고 지정 어종·등급의 새 시즌 물고기가 1마리 생겼는지 확인한다. 다른 물고기가 사라지거나 하트가 감소하면 불명확한 결과로 중단한다. 자연 하트 회복은 허용한다.
- 실패·시간 초과·미완료 요청이 남은 재시작에서는 자동 재시도하지 않는다. 완료된 제작 기록은 `craft-events`에 남기며 일반 결과 분포 학습과 분리한다.
- 시즌 정보·레시피가 누락되거나 순환/잘못된 재료 수량이 있으면 일반 교배·합성도 보류한다. 잘못된 레시피 때문에 필요한 재료가 일반 소모로 빠지는 일을 막는다.

## 목표 설정

```powershell
# 선택 사항: 각 어종의 5성 1마리씩. 완성하면 해당 어종 추가 제작 중단.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting On -SeasonGoal Highest

# 현재 설정과 새 설치 템플릿: 각 어종의 1~5성을 각각 1마리씩 보존하며 수집.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting On -SeasonGoal Collection

# 완성품이 있어도 각 어종의 5성 제작을 반복. 한 번에 다음 한 묶음만 예약.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting On -SeasonGoal Repeat

# 목표 등급/수량 변경. 등급 1~5, 수량 1~10.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonGoal Highest -SeasonTargetGrade 3 -SeasonTargetCount 2

# 시즌 작업과 자동 예약만 해제. 일반 자동화의 현재 실행 여부는 유지.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting Off
```

`-SeasonGoal`을 지정하면 생략한 목표 등급·수량은 각각 5와 1로 설정된다. 목표 설정만으로 Pause가 해제되지는 않는다. 전체 자동화를 켜려면 `-Mode Protected` 또는 `-Mode Economic`도 지정한다. 실행 중 0.4.0 미만 플러그인에 시즌 제작 활성화를 요청하면 스크립트가 거부한다. 먼저 정상 종료·업데이트·재시작해야 한다.

## 상태와 검증

`season_species_priority`는 어종 ID 배열이며 생략하면 위 시즌 2 우선순위를 사용한다. 목록 밖의 어종은 뒤에 어종 ID 순서로 붙는다. `collection`은 선택 어종의 요청된 모든 등급·수량을 채워야 다음 어종으로 넘어가고, `highest`는 목표 등급·수량을 채워야 넘어간다. `repeat`는 최우선 어종 제작을 계속 반복하므로 후순위 어종으로 자동 전환하지 않는다.

계획의 `species_priority`는 적용 순서, `focus_species`·`focus_name`은 현재 집중하는 어종이다. `needs`는 이 어종을 위한 일반 재료만 표시한다. 후순위 어종의 완성품이 있어도 수집 보존용 `reserved_ids`에는 계속 남는다.

게임의 `BepInEx/PCFishAutomation/season-review.json`에서 게임 언어의 어종명, 현재 시즌 레시피, 재료별 `required`·`reserved`·`missing`, `next_craft`를 읽을 수 있다. `snapshot.json`에도 같은 게임 쪽 계획이 들어 있다. 설정 변경 후 1~2초 안에 다시 계산한다.
