# 시즌 레시피 재료 보존과 자동 제작

0.5.0은 [시즌 수집과 일반 물고기 비축 정책](season-stock-policy.md)을 구현한다. 현재 시즌의 희귀도가 높은 어종부터 5성을 먼저 확보하고, 부족한 4·3·2·1성을 채운다. 전 어종 수집을 마치면 최상위 어종의 목표 등급을 반복 제작한다. 기존 수집 설정 `collection`을 유지해도 이 순서가 적용된다.

기본 설정은 `auto_season_craft=true`, `season_goal=collection`, `season_target_grade=5`, `season_target_count=1`이다. 비시즌에는 모든 일반 어종의 1~5성을 각각 15·12·9·6·3마리 비축한다. 일반 합성은 필요한 재료와 교배 부모를 보존하며, 0회 개체를 기본으로 사용한다. 횟수가 남은 개체는 어종·별 등급별 비축량의 3배에 도달한 초과분에서만 사용한다.

게임 실행 중 자동화가 켜져 있어야 진행하며 Pause/Observe는 새 제작도 중단한다. 설치와 실제 게임 적용은 별도다.

## 확인한 시즌과 레시피

현재 시즌 어종의 희귀도 내림차순으로 집중 대상을 정한다. 동일 희귀도에서만 `season_species_priority`의 사용자 순서를 사용한다. 시즌 2 자료에서는 도깨비불 해파리 → 누더기 프랑켄피시 → 호박 도깨비아귀 순서다. 현재 어종의 1~5성 수집이 끝나기 전에는 다음 어종으로 집중 대상을 바꾸지 않지만, 후순위 어종의 필요한 재료도 일반 합성에서 보호한다.

2026-11-06 실행 중인 게임의 `CommonData.seasonId=2`, 시즌 시작/종료 시각, `GameUtil.IsSeasonActive()`와 `CSVLoader.fishSeasonRecipeList`를 직접 읽었다. 현재 로드된 15개 레시피는 로컬 클라이언트의 시즌 2 테이블과 일치했다. 과거 테이블 파일이 있다는 이유로 그 시즌을 활성으로 취급하지 않는다.

## 재료를 남기는 방식

1. 희귀도가 가장 높은 미완료 어종을 선택하고, 그 어종에서 가장 높은 미완료 별 등급을 목표로 잡는다. 잠근 완성품도 목표 달성 수에 포함한다.
2. 현재 가진 하위 등급을 중간 재료로 활용한다. 해파리 2성이 한 마리뿐이어도 첫 5성을 만드는 데 사용할 수 있다. 수집용 2성을 남기려고 추가 2성을 먼저 만들지 않는다. 사용자 잠금·수동 예약은 해제하지 않는다.
3. 현재 목표 경로의 부족량과 전체 수집을 위해 남겨야 할 재료를 구분한다. 현재 경로의 재료를 우선 확보하면서 후순위 어종의 재료도 일반 합성에서 보호한다. 같은 어종·별 등급의 재고를 여러 경로에 중복 배정하지 않는다.
4. 자동 예약한 일반 재료는 일반 합성에서 제외하며, 기존 교배 조건을 만족하면 부모로 사용할 수 있다. 0회 개체도 시즌 재료가 될 수 있다. 사용자 잠금이나 수동 예약을 자동 비축으로 덮어쓰지 않는다.
5. 현재 목표 경로에서 실행 가능한 정확한 시즌 레시피가 있으면 먼저 제작한다. 결과가 확인되면 실제 재고로 다시 계산한다. 5성이 생기면 보존하고 부족한 4·3·2·1성을 채운다.
6. `collection`의 전 어종 목표가 완료되면 기존 수집품을 보존한 채 최상위 어종의 목표 등급을 반복 제작한다. 시즌 종료 시에는 일반 재료 예약을 모두 풀지 않고 비시즌 비축 기준으로 전환한다.

교배와 일반 합성은 현재 부족한 재료의 희귀도를 얻는 데 유리한 선택을 비교한다. 클라이언트 희귀도 예측만으로 특정 어종이나 별 등급을 확정 생성한다고 가정하지 않는다. Economic은 검증된 공동 결과 모델과 시세 자료가 있어야 판단하며, 활성 재료 목표에서는 부족한 어종·별 등급의 증가량을 우선한다. 점수는 판매 수익을 의미하지 않는다.

## 보호 조건과 실패 처리

- 사용자 잠금·`reserved_ids`·`reserved_species`·기본종은 시즌 제작에 사용하지 않는다. 잠금을 자동으로 풀지 않는다.
- 일반 재료는 선택한 시세 또는 Grade 보호도 통과해야 한다. 현재 `highest_buy_order`에서는 최고 매수 주문의 수수료 후 수령액이 1,000원 이하이면 허용하며, 확인된 주문 0건은 0원, 미확인 자료는 대기로 처리한다. 다음은 이전 판매 호가 정책의 설명이다. 0.4.17의 `market_merge_price_basis=best_observed_breeds`에서는 같은 어종·현재 별 등급의 실제 관측 매물 중 남은 교배 횟수가 가장 큰 상태를 고르고, 그 상태 매물들의 최고 판매자 호가가 1,000원 이하이면 제작 재료로 허용한다. 이론상 만교배 매물은 요구하지 않는다. 유효 매물 부재·가격 누락·만료는 판단 대기 사유다. `exact_breeds`에서는 이전 현재 개체의 횟수별 기준을 쓴다. Grade 모드에서는 보호 등급 이상의 일반 재료를 소비하지 않으므로 상위 시즌 제작이 대기할 수 있다.
- 자동 시즌 예약과 수동 예약을 합치지 않는다. Protected 계획기, Economic 계획기와 게임의 실행 직전 검사가 모두 교배용 보호와 일반 합성용 보호를 구분한다. 시즌 예약 개체여도 잠금·수동 예약·시세 보호·성숙·쿨타임·잔여 횟수·하트·보유 한도 조건을 통과해야 교배한다. 실제 시즌 물고기의 교배 금지는 유지한다.
- 현재 시즌의 이전 등급 시즌 물고기는 정확히 일치하는 상위 레시피에만 사용할 수 있다. 활성 시즌 물고기는 장터 거래가 제한되므로 그 중간 재료에 일반 장터 조회 완료를 요구하지 않는다. 잠금·수동 예약은 이 예외보다 우선한다.
- 게임 쪽에서 현재 레시피로 할당을 다시 계산해 명령의 시즌·결과 어종/등급·재료 ID 전체가 일치하는지 검증한다. 시즌과 레시피도 추천 버전 해시에 포함하며, 발송 직전 시즌이 계속 활성인지 다시 확인한다.
- 다른 통신·확인 대화상자·미확인 결과가 있으면 보내지 않는다. 0.4.32부터 메뉴·목록·교배 성공 화면을 열어둔 상태는 대기 사유가 아니다. 기존 세션/설정 해시/유효기간 검증과 `pending.json` 기록을 함께 사용한다.
- 게임의 성공 콜백 이후 지정 재료가 전부 사라지고 지정 어종·등급의 새 시즌 물고기가 1마리 생겼는지 확인한다. 다른 물고기가 사라지거나 하트가 감소하면 불명확한 결과로 중단한다. 자연 하트 회복은 허용한다.
- 실패·시간 초과·미완료 요청이 남은 재시작에서는 자동 재시도하지 않는다. 완료된 제작 기록은 `craft-events`에 남기며 일반 결과 분포 학습과 분리한다.
- 시즌 정보·레시피가 누락되거나 순환/잘못된 재료 수량이 있으면 일반 교배·합성도 보류한다. 잘못된 레시피 때문에 필요한 재료가 일반 소모로 빠지는 일을 막는다.

## 목표 설정

```powershell
# 선택 사항: 각 어종의 5성 1마리씩. 완성하면 해당 어종 추가 제작 중단.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting On -SeasonGoal Highest

# 현재 설정과 새 설치 템플릿: 각 어종의 5성부터 1성까지 수집한 뒤 최상위 어종 5성 반복.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting On -SeasonGoal Collection

# 완성품이 있어도 최상위 어종의 5성 제작을 반복. 한 번에 다음 한 묶음만 예약.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting On -SeasonGoal Repeat

# 목표 등급/수량 변경. 등급 1~5, 수량 1~10.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonGoal Highest -SeasonTargetGrade 3 -SeasonTargetCount 2

# 시즌 정책과 비시즌 비축을 해제. 일반 자동화 실행 여부는 유지하며 일반 합성은 0회 개체만 허용.
& 'C:\Project\PC-fish\scripts\Set-Automation.ps1' -SeasonCrafting Off
```

`-SeasonGoal`을 지정하면 생략한 목표 등급·수량은 각각 5와 1로 설정된다. 목표 설정만으로 Pause가 해제되지는 않는다. 전체 자동화를 켜려면 `-Mode Protected` 또는 `-Mode Economic`도 지정한다. 실행 중 0.4.0 미만 플러그인에 시즌 제작 활성화를 요청하면 스크립트가 거부한다. 먼저 정상 종료·업데이트·재시작해야 한다.

## 상태와 검증

`season_species_priority`는 같은 희귀도 어종의 순서를 정하는 ID 배열이다. `collection`은 현재 어종의 높은 별 등급부터 모든 요청 수량을 채운 뒤 다음 어종으로 이동하고, 전 어종 완료 후 최상위 어종의 목표 등급을 반복한다. `highest`는 각 어종의 목표 등급·수량만 채운 뒤 완료한다. `repeat`는 최상위 어종의 목표 등급을 계속 만든다. 기본 비시즌 비축량과 3배 기준은 어종별 1~5성 각 1마리 수집을 준비하는 고정 기준이며, 현재 부족량이 줄어도 0으로 바뀌지 않는다.

계획의 `phase`는 `collection`·`repeat`·`stockpile`, `focus_species`·`focus_name`·`focus_grade`는 현재 집중 어종과 목표 등급이다. `needs`는 현재 목표의 일반 재료별 `required`·`reserved`·`missing`을 표시한다. 비시즌에는 비축 부족분을 표시한다.

`stock`은 미보유 일반 어종까지 포함해 어종 × 별 등급별로 기준 비축량, 현재 필요량, 사용 가능한 재고, 보호된 재고, 부족량, 3배 기준, 0회 개체 수, 교배 부모 보호 수량, 보호 밖 초과량을 보여준다. `parent_ids`는 일반 합성에서 지킬 부모, `exhausted_ids`는 재료 확보용 0회 후보, `surplus_ids`는 3배 기준을 충족한 초과 후보다. 후보여도 합성 10마리와 별 등급·희귀도·시세 보호 조건을 다시 확인한다.

게임의 `BepInEx/PCFishAutomation/season-review.json`과 `snapshot.json`에서 계획을 확인한다. Python과 게임 쪽 모두 정책 버전 2를 사용해야 하며, 소비 직전에 게임 쪽에서 현재 재고로 다시 계산한다.
