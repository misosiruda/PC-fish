# PC FISH 자동화 안내 — 0.4.32

이 문서는 현재 동작과 설정을 설명한다. 설치는 [설치·업데이트 안내](installation.md), 공개 변경 사항은 [변경 이력](../CHANGELOG.md), 이전 정책과 실측 기록은 [개발 이력](automation-history.md)을 참고한다.

## 실행 방식

게임 실행 → BepInEx 플러그인 로드 → 저장된 설정 읽기 → Python 계획기 시작 순서로 작동한다. 별도의 Windows 시작 작업은 필요하지 않으며, 게임을 종료하면 진행하지 않는다. 마우스·키보드·포커스 전환 없이 기존 게임 함수를 호출한다.

새 설치의 기본값은 `enabled=true`, `mode=protected`, `protection_mode=market`이다. 자동 교배·합성·시즌 제작·수조 레벨업이 모두 켜져 있다. 메뉴·목록·교배 성공 화면이 열려 있어도 판단을 계속하지만 실제 통신·확인 대화상자·미확정 요청은 대기한다. 자동 교배는 화면의 부모 선택을 바꿀 수 있다.

## 켜기·끄기·상태

프로젝트 폴더의 PowerShell 7에서 실행한다. 게임 경로가 다르면 `-GameRoot '실제 게임 경로'`를 붙인다.

```powershell
& '.\scripts\Set-Automation.ps1' -Mode Status
& '.\scripts\Set-Automation.ps1' -Mode Pause
& '.\scripts\Set-Automation.ps1' -Mode Observe
& '.\scripts\Set-Automation.ps1' -Mode Protected -Protection Market -MergePriceBasis HighestBuyOrder
```

`Pause`와 `Observe`는 새 소비 작업을 보내지 않는다. 이미 보낸 요청의 결과 확인은 계속한다. 설정은 게임의 `BepInEx\config\pcfish-automation.json`에 저장되며 재시작 후에도 유지된다. DLL 업데이트에는 게임 재시작이 필요하다.

## 두 실행 모드

**Protected**는 보호된 개체를 제외하고 희귀도 진행을 위한 교배·대기·합성을 선택한다. 준비된 현재 부모와 곧 준비될 부모, 하트와 수용량을 고려한다. 시세 보호는 소비할 수 있는 물고기를 가려내는 기준이며 수익 기대값 최적화가 아니다.

**Economic**은 JSON으로 준비한 가격·판매 가능성·어종과 별 등급의 공동 결과 모델을 사용한다. 자료가 부족하면 판단을 보류하며 임의의 확률로 채우지 않는다. 설정의 `economic_model_file`에 모델 경로를 지정하고 `Set-Automation.ps1 -Mode Economic`으로 선택한다. [계획기 계약](planner-contract.md)을 따른다.

## 일반 합성

일반 재료 **10마리**, **별 등급(Grade) 동일**, **희귀도(Level) 차이 최대 1**이 조건이다. 어종과 남은 교배 횟수는 달라도 된다. Protected는 같은 희귀도 묶음을 우선하고, 없을 때 인접 희귀도를 섞는다. 기본종은 일반 합성 재료로 쓰지 않는다.

클라이언트 예측의 최저 결과 `min(5, floor(희귀도 합계 / 10) + 1)`가 가장 높은 재료보다 낮으면 차단한다. Economic은 결과 모델에 가장 높은 재료보다 낮은 결과가 하나라도 있으면 추가로 차단한다. 이 검사는 클라이언트 예측과 입력 모델에 대한 조건이며 실제 서버 확률 전체를 증명하지 않는다.

잠금·수동 예약·시즌 수집품·현재 시즌의 필요한 일반 재료·시세 미확인 개체는 보호한다. Python의 계획과 게임의 실행 직전 검사에 같은 조건을 적용한다.

## Steam 장터 가격에 따른 자동 잠금

현재 기본 기준은 `market_merge_price_basis=highest_buy_order`다. 같은 어종·별 등급의 **최고 매수 주문에서 Steam·게임 수수료를 뺀 수령액**을 교배·일반 합성·시즌 제작에 공통 적용한다.

| 조회 결과 | 처리 |
| --- | --- |
| 검증된 수령액 1,000원 이하 | 다른 잠금·예약·행동 조건을 확인한 뒤 후보로 허용 |
| 검증된 수령액 1,000원 초과 | 소비 후보에서 제외하고 실측 시세에 따라 자동 잠금 |
| 명시적으로 매수 주문 0건 확인 | 즉시 판매 가치를 0원으로 평가. 다른 보호 조건은 유지 |
| 조회 실패·미확인·만료·상품/통화/수수료 근거 불일치 | 임시 보호하고 조회 대기 |

매수 주문의 상품명·통화·가격별 수량·최고 주문과 공개 판매 매물의 수수료 근거를 검증한다. 게임에서도 원자료로 수령액을 재계산한다. 정확히 1,000원은 허용하고, 이미 잠긴 개체는 가격이 내려가도 자동으로 풀지 않는다. 현재 주문은 이후 체결이나 판매 수익을 보장하지 않는다.

신규 미등재 일반종은 같은 희귀도·별 등급의 기존 일반종 전체를 비교해 최고 순수령액으로 추정한다. 실측 주문과 구분하며 추정가로 영구 잠금을 걸지 않는다. 매물이 이미 관측된 상품은 주문 조회에 실패해도 미등재로 오인하지 않고 보호한다. 시즌 한정종은 일반종 비교 대상에서 제외한다.

조회는 Selenium이 별도 임시 프로필의 숨김 Chrome으로 공개 장터 페이지를 읽는다. 개인 Chrome·로그인·쿠키·API 키를 사용하지 않는다. 한 번에 한 상품을 조회하며 어종·별 등급별 캐시를 24시간 공유한다. 기본 상품 간격은 120초이며 서버 제한·연결 실패 때는 백오프한다. 게임 메인 스레드는 Chrome 응답을 기다리지 않는다.

기존 `exact_breeds`, `full_breeds`, `best_observed_breeds`는 호환용 선택지로 남아 있다. 이 정책들의 판매 호가·교배 횟수별 기준은 [개발 이력](automation-history.md#steam-장터-가격에-따른-자동-잠금)에 있다. 기존 설치의 선택값은 업데이트로 자동 변경하지 않는다.

별 등급만으로 보호하려면 `Set-Automation.ps1 -Mode Protected -Protection Grade`를 사용한다. 기본 `protect_grade_at_least=3`은 일반 3성 이상을 보호하므로 상위 시즌 제작이 대기할 수 있다.

## 시즌 재료 자동 보존과 제작

게임에서 현재 시즌 ID·활성 기간·레시피를 읽는다. 기본 목표는 어종별 1~5성 각 1마리이며 **해파리 → 프랑켄피시 → 아귀** 순서로 미완료 어종 하나에 집중한다. 현재 목표를 마치기 전에는 후순위 어종의 일반 재료를 미리 예약하지 않는다.

수집품은 남기고 상위 제작에 필요한 중간 물고기를 추가 확보한다. 자동 예약한 일반 재료는 일반 합성에서 제외하지만, 별도 보호와 교배 조건을 만족하면 부모로 사용할 수 있다. 사용자 잠금·수동 예약은 제작에서도 유지한다. [시즌 제작과 목표 설정](season-crafting.md)에 상세 조건이 있다.

## 교배 결과와 서버 복구

교배는 원래 `UIBreed.Breed`와 성공 핸들러로 물고기 등록·부모 횟수·하트 차감·저장을 처리한다. 저장 뒤 최소 60초를 둔 조회로 서버 재고를 확인한다. 성공 응답의 새 UID가 서버 목록에 없으면 해당 조회 응답에 연결된 원래 `ManageRestore` 복구 결과를 검증한 뒤 새 요청을 판단한다.

미확정 요청을 그대로 다시 보내지 않는다. 복구 중 하트 회복 시각을 직접 설정하거나 경험치·하트 비용을 별도로 보정하지 않는다. 기존 요청·차감 기록은 보존하고 새 교배는 새 요청 ID로 실행한다. 연속 복구에는 증가하는 대기 간격을 적용한다.

계획기는 시세·이력 처리 후 최신 스냅샷을 다시 읽고 세션·설정 일치를 검사한다. 기존 5초 상태 유효성 제한을 유지한다. 소비 직전에는 게임 쪽에서도 현재 상태를 다시 검증한다.

## 수조 레벨업과 표시

경험치 조건을 충족하면 기존 게임 레벨업·보상·확장 함수를 사용하며 전용 레벨업 완료 팝업을 처리한다. 실제 레벨이 올라가면 진행된 것으로 기록한다. 경험치·성장도·보상 표시가 예측과 다르다는 이유만으로 전체 자동화를 멈추지 않는다.

레벨업이나 표시 갱신만 실패하면 해당 기능을 보류하고 교배·합성은 계속한다. 실제 물고기 소실·예기치 않은 소비·사용자 잠금 해제는 별도로 차단한다. 하트·레벨·경험치 표시는 기존 게임 갱신 함수로 실제 데이터와 맞춘다.

## 상태와 기록

게임 폴더의 `BepInEx\PCFishAutomation`에 기록한다.

| 파일/폴더 | 내용 |
| --- | --- |
| `status.json`, `worker-status.json` | 모드 버전·실행 상태·계획기 상태 |
| `snapshot.json`, `recommendation.json` | 읽은 게임 상태와 다음 행동 |
| `market-review.json`, `market-cache.json` | 개체별 시세 판단과 상품별 캐시 |
| `season-review.json` | 현재 집중 어종·필요/보유/부족 재료 |
| `pending.json` | 결과 확인 중인 요청 |
| `market-lock-events`, `craft-events` | 자동 잠금과 시즌 제작 기록 |

미확정 요청 기록을 지워 대기를 해제하지 않는다. 게임의 `.es3` 세이브를 모드가 직접 덮어쓰지 않으며, 상태 파일에는 개인 재고가 포함될 수 있으므로 공개 이슈에 전체 폴더를 첨부하지 않는다.

## 검증 범위

각 공개 버전의 검사와 배포 자산 정보는 해당 [릴리즈 노트](https://github.com/misosiruda/PC-fish/releases/tag/v0.4.32)에 기록한다. Python 계획기 검사, C# 실행 보호 검사, 실제 게임 참조 빌드, 패키징·설치 검사는 서로 다른 근거다.

과거 설치본에서 관찰한 교배·합성 결과는 [개발 이력](automation-history.md)에 시점별로 남아 있다. 이를 새 패키지의 장시간 안정성, 모든 시즌 제작 경로, 서버 확률 또는 수익성 검증으로 확대하지 않는다.
