# 계획기 입력 및 판단 계약 v1

## 시간과 가치

실제 연결에서는 모든 시각을 같은 Unix 초 단위로 전달한다. `ready_at`, `now`, `next_heart_at`, `captured_at`은 같은 기준이어야 한다. 합성 예제는 계산을 읽기 쉽게 0초에서 시작한다. `ready_after_seconds`는 행동 완료 이후의 기간이다.

기본 계획은 30분이며 상태를 바꾸는 행동 3회까지 탐색한다. `action_seconds=1`은 직렬 요청 처리 지연의 초기 가정이고 서버 응답 실측값이 아니다. 일반 부모 회복 기본값 180초도 실제 응답의 `BreedNextDatetime`으로 덮어써야 한다. 기본종의 성장 회복에는 별도 모델이 필요하다.

`quotes`의 키는 `(species, grade, remaining_breeds)`다. 잔여 횟수별 근거가 없으면 입력에서 그 가격을 확정하지 말고 해당 키를 비워 둔다. `net_proceeds`는 판매자에게 적립될 금액이다. 매수자 총액을 그대로 넣으면 잘못된 평가가 된다. `sale_probability`는 0~1의 기간 내 판매 확률을 입력하며, 현재 프로그램은 거래량에서 이 값을 자동 추정하지 않는다.

한 스냅샷 안에서는 가격을 고정한다. 모든 판매 확률에는 동일한 평가 기간을 사용해야 한다. 이 기간은 입력을 만드는 연결부에서 통일하며 계획 범위 30분과 같을 필요는 없다. 가격 변화·시장 충격·다량 판매로 인한 주문 소진은 모델링하지 않는다. 같은 상품을 많이 생산하는 계획은 별도 수요 용량 검증이 필요하다. `discount_rate_per_hour`는 사용자 시간 선호의 선택 설정이며 기본값은 0이다.

## Fish

필수 필드: `id`, `species`, `level`, `grade`, `remaining_breeds`. 결과 템플릿과 규칙 부모에서는 ID가 필요하지 않다.

- `ready_at`: 이 물고기가 다시 교배 가능해지는 시각. 성장 조건을 포함해 연결부에서 결정한다.
- `breed_allowed` / `merge_allowed`: 게임의 정상 조건을 연결부가 확인한 결과다.
- `protected_breed`: 교배에 사용하지 않을 개체.
- `protected_merge`: 합성 잠금. 이 필드만으로 교배를 막지는 않는다.
- `reserved`: 레시피나 사용자 보관을 위해 합성에서 제외.
- `seasonal`: 일반 합성에서 기본 제외. 일반 교배/합성 결과로 시즌 물고기를 생성하는 규칙은 거부한다.
- `unlimited_breeding`: Level/Grade 0의 기본종에만 명시할 수 있다. 숫자 0을 자동으로 무한 횟수로 해석하지 않는다.
- `breed_recovery_seconds`: 개체별 교배 후 회복 기간. 기본종에는 필수로 제공해야 한다.

`id`는 스냅샷 내에서 유일해야 하며 `planned:` 접두어는 계획기의 임시 결과용으로 예약된다. 모르는 물고기 필드는 오타로 보호 설정이 누락되는 일을 막기 위해 거부한다.

## 공동 결과 규칙

부모는 `(species, level, grade, remaining_breeds, unlimited_breeding)` 특성의 멀티셋으로 매칭한다. 부모 순서의 효과는 모델링하지 않으며 순서 비의존성을 확인해야 한다. 보호 플래그와 준비 시각은 규칙 키에 들어가지 않고 현재 행동 가능 여부에 사용한다.

교배 규칙은 부모 두 마리, 합성 규칙은 재료 열 마리를 지정한다. 동일 특성의 재료는 `count`로 묶어 입력할 수 있다. 각 결과에는 다음을 모두 명시한다.

- `probability`: 양수이며 모든 결과의 합이 1.
- `fish.species`, `level`, `grade`, `remaining_breeds`.
- `fish.ready_after_seconds`: 결과물의 교배 준비 기간. 모르는 시간을 0으로 생략하지 않는다.

`evidence`는 `verified`, `observed`, `assumption`, `synthetic` 중 하나다. 원본·관측 경로를 `source`에 기록한다. `observed`는 기본 `sample_count>=30`이 필요하다. 이는 실행 검증이나 서버 규칙 증명이 아니며, 드문 미관측 결과를 배제할 수 없다.

Grade/어종 조건이 다른 부모의 규칙을 무조건 재사용하지 않는다. `probabilities.py`의 클라이언트 Level 표는 별도의 참고 함수이며, 실제 공동 결과 규칙의 빈 부분을 채우는 기본 분포가 아니다.

## 상태 전이와 비용

교배는 하트 1개를 사용하고 부모의 유한 횟수를 1 감소시킨다. 두 부모의 준비 시각을 갱신하고, 확률 분기별 자식 한 마리를 추가한다. 합성은 보호되지 않은 일반 재료 열 마리를 제거하고 결과 한 마리를 추가한다. 남은 교배 횟수가 있는 재료도 허용하며, 실제 잔여 횟수에 맞는 결과 모델과 가격이 필요하다. 재료 전액의 기회비용을 차감하는 계산은 유지한다.

교배 보상은 `결과물 가치 + 부모 사용 후 가치 - 부모 사용 전 가치 - 행동 비용`이다. 합성 보상은 `결과물 가치 - 재료 총가치 - 행동 비용`이다. 이후 상태에서 얻을 수 있는 보상을 같은 계획 종료 시점까지 확률 가중해 합한다. 변경되지 않은 물고기 가치는 상쇄되므로 알 수 없는 다른 개체를 0원으로 대체하지 않는다.

하트 타이머는 상한에서 회복을 멈추고 추가 횟수를 적립하지 않는다. 후속 조사에서 확인한 `UIBreed` 성공 콜백은 상한에서 교배할 때 소비 직전에 회복 기준 시각을 초기화한다. 따라서 정상 교배에서 가득 찬 하트 한 개를 쓰면 다음 회복은 행동 완료 후 420초다. 타이머 함수만 분석했을 때의 즉시 회복 해석을 이 성공 콜백 근거로 정정했다.

실행 스냅샷의 `next_heart_at`은 Unix 정수 시각과 회복 간격을 double 정밀도로 합산한다. `long + float`의 암묵적 float 변환으로 큰 Unix 시각이 반올림되는 계산은 사용하지 않는다. 원래 게임 순서 교배의 이벤트는 실제 저장 완료 시각과 지연 서버 확인 시각을 따로 보관하며, 결과 준비 대기시간은 실제 저장 완료 시각을 기준으로 기록한다. 관측 시점을 바꾼 제한 비교 이벤트(`flow=native_comparison`)는 일반 계획 학습에서 제외한다.

## 출력

- `action.kind`: `breed`, `merge`, `wait`, `hold`.
- `action.fish_ids`: 다음 행동에서 사용할 ID. `wait`이면 `until`에 재평가 시각.
- `expected_inventory_value_gain`: 제한된 계획 범위에서의 기대 재고 가치 변화. 판매 매출이나 보장 수익이 아니다.
- `alternatives`: 같은 입력에서 비교한 후보들. 노드 예산에 걸리면 계산한 범위의 값이다.
- `data_requirements`: 누락·오래된 시세, 공동 결과 규칙, 기본종 회복 모델 등.
- `merge_protected_fish_ids`: 현재 일반 합성에 사용하지 않는 개체.
- `input_sha256`: 추천을 만든 입력 식별자. 실행 연결부는 실제 상태가 바뀌었으면 추천을 폐기해야 한다.
- `search.limits`: 후보/노드/대기 사건 제한에 걸렸는지. 제한이 없어도 유한 계획 범위의 결과이며 전역 최적을 주장하지 않는다.
- `execution_supported`: 항상 false. 이 버전은 게임이나 장터를 조작하는 코드가 없다.

요청 진행 중이거나 직전 결과가 불명확하면 우선 `hold_pending_reconciliation`을 반환한다. 현재 입력의 보유 상태와 완료 여부를 확인한 뒤 다시 계획한다.

## 미구현 범위

라이브 게임 어댑터, 이벤트 자동 수집, 실제 교배·합성 호출, Steam 거래 등록, 시즌 제작, 가격 예측, 판매 확률 추정은 포함하지 않는다. 현재 실행 가능한 것은 JSON 입력에 대한 독립 계획기와 관측 JSONL의 빈도 집계다.
